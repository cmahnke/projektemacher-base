IIIF

IIIF support

This theme generates IIIF resources at three levels:

  • Manifests (Presentation API) — one manifest per page opt-in, rendering the page’s resources as canvases. Plain images (resources without an Image API path) are embedded directly, GLB model resources become Presentation 4 Scene containers (see Page metadata), and a two-sided “leaflet” layout can be triggered with the hint: leaflet-front / leaflet-back resource params — see Page metadata. Selected via the iiif-manifest output format.
  • Collections (Presentation API) — aggregations of manifests on home and term pages. Selected via the iiif-collection output format.
  • Images (Image API) — tile generation is handled outside of Hugo, see scripts/iiif.sh.

Presentation API versions

Version Status Context
3 Default, stable http://iiif.io/api/presentation/3/context.json
4 Draft (4.0.0-draft) http://iiif.io/api/presentation/4/context.json

The version is selected per page or globally, see Presentation 4.

Presentation API 2 is no longer supported

Generation of Presentation API 2 manifests (the former iiif output format with sc:Manifest/sc:Sequence vocabulary, templates _default/single.json and _default/single.iiif.json) has been phased out. Building a page still using iiifContext with a presentation/2 context aborts the build with an error.

Migration path:

  1. Set outputs to include iiif-manifest instead of iiif
  2. Move manifest front matter to the iiif. namespace, see Page metadata. Notably iiifMetadata → iiif.metadata and iiifStructure → iiif.structure
  3. iiifAttribution is replaced by iiif.requiredStatement, iiifLogo by iiif.logo
